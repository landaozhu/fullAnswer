## 强缓存

强缓存 = 缓存还新鲜时，浏览器**直接用本地副本，不发请求**。DevTools 里仍是 200，Size 列写 `from memory cache` 或 `from disk cache`。

但这**不是**「响应里出现 `Cache-Control` 就会强缓存」。`Cache-Control` 是一组指令，服务端用它告诉浏览器：**能不能存、能不能直接用**。只有 `max-age > 0`（还在有效期内）才走强缓存。

### 会走强缓存：`max-age`

图片、CSS 这类不常改的资源，服务端带 `Cache-Control: max-age=1200`（秒）。浏览器把资源存本地。

下次要这个资源时：

- **没过期**：直接用，不发请求。200 + `from memory cache` / `from disk cache`（谁进内存谁进硬盘由浏览器自己判，一般小文件内存、大文件硬盘）。
- **过期了**：再发请求。配了协商缓存（ETag / Last-Modified）就走协商；没配就返回最新资源 + 200 + 新的 `Cache-Control`。

HTTP/1.0 用 `Expires`（绝对时间），HTTP/1.1 用 `max-age`（相对时间）。两者都有时以 `Cache-Control` 为准。

### 不会走强缓存：`no-cache` / `no-store`

名字容易误导。先问两件事：能不能存？用之前要不要问服务器？

| 指令 | 能不能存本地 | 用之前问不问服务器 | 结果 |
| --- | --- | --- | --- |
| `max-age=1200` | 能 | 有效期内不问 | 强缓存，200 from cache |
| `no-cache` | **能** | **每次都问** | 协商：没改 304，改了 200 |
| `no-store` | **不能** | 无从问起 | 禁止缓存，每次完整网络 200 |
| `max-age=0` | 能 | 一存就过期，下次必问 | 效果接近 `no-cache`，语义是「新鲜度为 0」 |

- **`no-store`：不缓存。** 浏览器和中间代理都**不准存**这份请求/响应。每次都是完整网络 200，没有 304，也没有 from cache。登录态、个人信息等敏感接口用这个。它**不是**「不加过期时间」，也不是强缓存的一种，而是根本不进缓存。
- **`no-cache`：能存，但不能当强缓存用。** 本地可以留副本，但每次用之前必须带条件请求去服务器协商。名字叫 no-cache，实际是「禁止不经验证就用」。
- **`max-age=0`：** 一存进去就过期，下次不会 from cache。语义管新鲜度，`no-cache` 管「用之前必须再验证」。常见写法 `Cache-Control: max-age=0, no-cache`。

口述口诀：`max-age>0` 才是强缓存；`no-cache` 是协商；`no-store` 是禁止缓存。

### 注意

- `from memory cache`：内存，关标签页就没了。
- `from disk cache`：硬盘，关浏览器还在。
- 谁进内存谁进硬盘浏览器自己判，`Cache-Control` 指定不了。

## 协商缓存


当缓存过期（Catch-Control）的时候，会请求服务端，根据Etag（请求头If-None-Match）判断资源是否为最新。如果是最新，直接返回304，表示资源未被加载，如果不是最新，且没有Last-Modifined，就会返回200+最新资源+最新Etag字符串
如果有Last-Modified（请求头If-Modified-Since），服务端就会检查修改时间是否一致，如果一致，返回304，告诉浏览器资源未修改，否则返回200+最新资源+最新资源修改时间



### Etag


资源对应的唯一标识，是这个服务端生成的一个hash值，返回给浏览器，浏览器请求的时候带上请求键名，If-None-Match,值为Etag字符串，当再次请求到服务的时候，服务端会对浏览器的Etag字符串和服务端端Etag字符串进行对比。



### Last-Modified

最新资源修改时间，浏览器第一次访问服务端时，服务端会返回资源和修改时间标识Last-Modified，浏览器再次请求时，请求头带上If-Modified-Since，那么服务端就会查看着两者是否一致



### 注意


Etag和Last-Modified可以都有，也可以只有一个，如果两者都存在，建议先判断Etag。比如说修改了一个文件，改完又改回去，修改时间Last-Modifed变了，但文件没变化。那这个时候Etag是不变的，所以Etag会更准确。

## 追问

### 追问 1：`no-cache` / `no-store` / `max-age=0`

【一句话】**no-cache 能存但每次必须协商；no-store 根本不存；max-age=0 立刻过期，下一步还是去协商。**

- **no-cache**：浏览器**可以**把副本放本地，但每次用之前都要带条件请求去服务器问一声（`If-None-Match` / `If-Modified-Since`）。没改 → 304 用本地；改了 → 200 新资源。不是「禁止缓存」。
- **no-store**：敏感接口用。浏览器、中间代理都**不准存**，每次都是完整网络 200，没有 304 这条路。
- **max-age=0**：强缓存立刻过期，下一次不会直接 200 from cache，会去服务器校验。效果接近 no-cache（都是「先问再决定」），但语义不同：`max-age` 管的是新鲜度，`no-cache` 管的是「用之前必须再验证」。常见写法 `Cache-Control: max-age=0, no-cache`。

口述顺序：能存吗 → 用之前要不要问服务器 → 可能 304 还是必 200。

### 追问 2：内存还是硬盘？为什么优先 ETag？

**内存 / 硬盘：你配不了，看 DevTools Size 列。**

- `from memory cache`：内存。当前进程里的小文件（JS / CSS）常见。关标签页就没了，再开要重新取（可能再走 disk 或网络）。
- `from disk cache`：硬盘。图片、字体等较大资源常见。关浏览器还在，下次还能用。
- 谁进内存谁进硬盘由浏览器自己判（体积、类型、当前内存压力），面试别说成 `Cache-Control` 能指定。强缓存命中都是 200，靠 Size 列区分，不是靠状态码。

**ETag 优先于 Last-Modified：**

- Last-Modified 精度只有 **1 秒**，一秒内改多次看不出来。
- 文件改了又改回去：修改时间变了，内容没变，Last-Modified 会误判「过期」，ETag（内容 hash）不变，仍 304。
- 两者都有时，请求会带 `If-None-Match` + `If-Modified-Since`，服务器**先比 ETag**；ETag 一致就 304，不必再信时间。

口述：时间戳不准 + 改回去内容没变；hash 看的是内容。
